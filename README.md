# СЭД - Система электронного документооборота для государственных учреждений

Полнофункциональная веб-система управления документооборотом для государственных организаций Узбекистана на базе Django 5.2.

## 🎯 Обзор

Система предназначена для управления входящими, исходящими, внутренними документами и обращениями граждан. Включает:

- **Ролевую модель доступа** с 5 ролями (Гражданин, Секретарь, Руководитель, Исполнитель, Администратор)
- **Жизненный цикл документа** от создания до архивирования
- **Систему резолюций** с назначением исполнителей
- **Цифровую подпись (ЭЦП)** для утверждения
- **Аудит логирование** всех действий
- **Уведомления** и напоминания
- **Печать и экспорт** документов

## 📖 Использование

### Вход в систему

1. Перейти на http://127.0.0.1:8000/login/
2. Введите учетные данные (см. ниже)
3. Система перенаправит вас на персональный dashboard

### Подача обращения (для граждан)

1. Перейти на http://127.0.0.1:8000/appeal/
2. Заполнить форму обращения
3. После подачи получите регистрационный номер
4. Проверить статус можно по этому номеру на http://127.0.0.1:8000/appeal/{номер}/

### Регистрация документа (для секретарей)

1. Перейти в "Документы" → "Новый входящий"
2. Заполнить данные документа
3. Система автоматически сгенерирует номер
4. Сохранить и передать на резолюцию

### Создание резолюции (для руководителей)

1. Открыть документ
2. Нажать "Создать резолюцию"
3. Выбрать исполнителя
4. Указать текст и срок
5. Подписать ЭЦП (цифровой подписью)

### Выполнение задачи (для исполнителей)

1. Перейти в "Мои задачи"
2. Открыть назначенную резолюцию
3. Загрузить отчет о выполнении
4. Отметить как завершено

6. Регулярно обновлять зависимости
7. Использовать real ЭЦП вместо симуляции

## 📊 Модели данных

### User (Пользователь)

- id, username, password, email
- full_name (ФИО)
- role (Citizen, Secretary, Head, Executor, Admin)
- department (FK)
- phone, is_active

### Department (Отдел)

- id, name, code
- description
- users (обратная связь)

### Document (Документ)

- id, reg_number (уникальный)
- title, content
- doc_type (IN, OUT, INT, APP)
- status (DRAFT, REGISTERED, SENT, RECEIVED, RESOLUTION, IN_PROGRESS, DONE, OVERDUE)
- file (optional)
- sender_org, sender_person
- author (FK User), assigned_to (FK User)
- deadline, created_at, updated_at

### Resolution (Резолюция)

- id, document (FK), author (FK), executor (FK)
- text (текст резолюции)
- due_date, created_at
- is_completed, completion_note, completed_at
- is_signed, signed_by (FK), signed_at
- signature_data (ЭЦП)

### DocumentHistory (История)

- id, document (FK)
- old_status, new_status
- changed_by (FK), changed_at
- note

### Notification (Уведомление)

- id, user (FK), document (FK)
- notification_type, title, message
- is_read, created_at

### AuditLog (Лог аудита)

- id, user (FK), action
- object_type, object_id, object_str
- changes (JSON), ip_address
- timestamp

## 🐛 Известные проблемы и решения

### Проблема 1: Загрузка файлов

**Статус:** ✅ Реализовано

- Поле `file` в документе поддерживает загрузку
- Файлы сохраняются в `documents/YYYY/MM/`

### Проблема 2: Просрочено документы

**Статус:** ✅ Реализовано

- Метод `is_overdue()` в модели Document
- Автоматическое выделение красным в шаблонах

### Проблема 3: Цифровая подпись

**Статус:** ✅ Реализовано (простая версия)

- Поля `is_signed`, `signed_by`, `signed_at` в Resolution
- Полная интеграция с реальной ЭЦП требует доп. настройки

### Проблема 4: Уведомления

**Статус:** ✅ Реализовано

- Создаются при назначении резолюций
- Создаются при завершении задач
- Система отметки как прочитанного
